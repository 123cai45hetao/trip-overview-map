# 行程总览 Trip Overview ✈️

输入入住酒店和想去的目的地，在一张地图上看到全部地点的分布、真实路线与智能排程后的行程单。纯静态网页，无需后端、无需安装，克隆即用。

![screenshot](docs/screenshot-desktop.png)
![screenshot-mobile](docs/screenshot-mobile.png)

## ✨ 功能

- 🔍 **搜索即添加**：输入酒店和景点名称，基于腾讯位置服务实时联想，选中即上地图
- 🧠 **智能排序**：多策略求最短总耗时访问顺序——最近邻贪心构造初始解 + 2-opt 局部改进 + 状态压缩 DP 求精确最优，多策略兜底，取可行最短方案
- ⏱ **锚点排程**：每个景点可设定到达/离开时间锚点，算法在满足锚点约束的前提下排程；免费景点默认停留 1 小时，可闭环回到酒店
- 🚗 **真实路线**：基于路线规划 API 计算两两通行时长（而非直线估算），支持驾车/步行/公交多种出行方式
- 🔢 **路线编号**：地图路线按访问顺序标注数字编号，可一键开关路线显示
- ⌚ **宽松时间输入**：`9:00-11:30`、`9点~11点半`、`上午9点到下午2点` 均可识别
- 📊 **行程统计**：目的地数量、总直线距离、总驾车距离一目了然
- 💾 **本地保存**：行程自动存在浏览器 localStorage，刷新不丢，不上传任何服务器
- 📱 **移动端适配**：手机上自动变为底部抽屉布局，含地图健康看门狗自愈

## 🧩 技术实现

- **接口数据获取**：封装地图路线规划 API，请求侧做 QPS 节流 + 指数退避重试 + 仅缓存成功结果；弱网、断网、服务失败场景均有降级路径
- **时间矩阵构建**：N 个景点两两请求真实通行时长，构建 N×N 时间矩阵（含 A→B / B→A 双向，天然非对称）；当前按输入顺序节流请求，未做批量接口合并
- **访问顺序优化**：最近邻贪心保底有解 → 2-opt 局部改进 → 小规模（N ≤ 10）状态压缩 DP 求精确最优；排程层支持时间锚点约束（超时剪枝 DP）
- **异常处理**：单条腿请求失败不阻塞整体，排序失败保证按钮状态复位；前端渲染层 try/catch + 移动端地图看门狗（塌陷自愈、视口漂移重算）
- **测试**：基于 Puppeteer 的端到端自动化测试，覆盖主流程、锚点排程、宽松时间解析、断网、弱网重试、服务失败降级、移动端视口与抽屉交互

## 🚀 快速开始

### 1. 获取腾讯地图 Key（免费）

1. 打开 [腾讯位置服务控制台](https://lbs.qq.com/dev/console/application/mine)，注册 / 登录
2. 创建应用 → **添加 Key**，同时勾选 **WebServiceAPI** 和 **JavaScriptAPI GL**
3. 建议配置「域名白名单」保护你的 Key（个人使用加自己的域名即可）

### 2. 运行

```bash
git clone https://github.com/<你的用户名>/trip-overview-map.git
cd trip-overview-map
# 直接双击 index.html，或起一个本地服务：
python -m http.server 8080
```

打开页面，粘贴你的 Key，即可使用。Key 保存在你自己浏览器的 localStorage 里，**不会被写入代码、不会被提交到 Git**。

### 3. 部署到 GitHub Pages（可选）

仓库 → Settings → Pages → Source 选 `main` 分支根目录，保存即可获得一个公开链接分享给别人。

## 🔑 关于 Key 的安全说明

- 本项目**不内置任何 Key**，首次打开会引导使用者填入自己的 Key
- Key 仅存于使用者本机浏览器，不会随代码提交
- 公开部署时强烈建议在腾讯位置服务控制台为 Key 配置**域名白名单**，防止被盗用
